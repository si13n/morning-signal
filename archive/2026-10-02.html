GitHub Actions: macOS 14 runner image retirement (Nov 2, 2026)

GitHub announced retirement of the macOS 14 (Sonoma) Actions runner image effective November 2, 2026, with multiple October brownouts. Workflows should migrate to macos-15 or macos-latest (macos-26) labels now.

Why it matters

macOS runners host iOS/macOS UI tests (XCUITest, Appium) and simulators—update workflow labels and validate toolchains to avoid CI failures and longer queue times.

Accessibility testing2/10

EN 301 549 v4.1.1 adopts WCAG 2.2 — BrowserStack: prepare testing pipelines

ETSI’s EN 301 549 v4.1.1 (adopting WCAG 2.2) raises interactive and platform-preference criteria. BrowserStack recommends integrated automated, semi-automated, and real-device testing for web and native apps.

Why it matters

New success criteria require active interaction and real-device checks; QA must add WCAG 2.2 checks into CI and real-device suites to avoid regressions and procurement issues.

Test evidence & observability2/10

Actions retention now covers checks, workflow runs, and statuses

Starting October 1, 2026, GitHub Actions retention settings apply to checks, workflow runs and statuses (default 90 days), aligning them with artifact/log retention and shortening historical availability.

Why it matters

Flaky-test history, triage evidence and test-forensics windows shrink—QA leads must review retention, export or archive critical runs, and adjust policies before data is evicted.

CI stability / coverage tooling3/10

Code coverage uploads no longer fail CI for new branches

The GitHub Code Quality upload-code-coverage action no longer fails CI when pushing a branch that has no open pull request; it now skips uploads until a PR exists and explains why in the step summary.

Why it matters

Eliminates false CI failures for new branches and reduces noisy broken pipelines—QA teams can simplify coverage workflows or add pull_request triggers for immediate uploads.
