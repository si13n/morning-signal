GitHub adds AI Scan metrics to Security Overview (public preview)

GitHub added an AI Scan tab and metrics in Security Overview showing total AI Scan findings, remediation rate, repos producing findings, trends, and autofix application counts (public preview on Oct 13, 2026).

Why it matters

QA leads can now measure AI-assisted scan coverage, autofix adoption, and remediation trends to calibrate test policies and evaluate AI-sourced findings' reliability.

Test Evidence / Governance2/10

Audit events for GitHub Code Quality finding dismissals and reopenings

GitHub added two audit-log events that record manual dismissals and reopenings of Code Quality findings, including who acted, when, repository, rule, and affected finding identifiers (GA on GitHub Enterprise Cloud, Oct 13, 2026).

Why it matters

Traceability for manual finding changes enables QA leads to investigate dismissed rules, correlate with test backlog changes, and enforce review policies for test-quality exceptions.

Test Infrastructure / Security for QA3/10

Secret scanning: Anthropic keys blocked by default; Salesforce partner added

GitHub secret scanning now detects Anthropic and Cloudsmith keys, blocks Anthropic service/user keys with push protection by default, and adds Salesforce as a secret-scanning partner (Oct 13, 2026).

Why it matters

Prevents model API keys and other provider secrets from entering repos or CI — critical for safe test fixtures, device-farm configs, and protecting test environment credentials.

CI/CD pipeline observability: framework to diagnose flaky tests and pipeline failures

JetBrains published a practical framework for CI/CD pipeline observability: what signals to collect (queue times, flaky-test rate, agent utilization), how to connect CI context to metrics, and tool trade-offs for investigation depth.

Why it matters

Observability choices directly impact flaky-test triage speed and root-cause analysis; the framework helps QA leads pick metrics and tools that surface test-level causes, not just infra symptoms.
