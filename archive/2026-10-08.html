Playwright v1.64.0: WebMCP test access, improved test runner and video options

Playwright v1.64.0 adds experimental WebMCP support (page.webmcp / frame.webmcp) so tests can enumerate and call page-registered tools, plus new test-runner options (shuffle, project defaults) and higher-fidelity video settings.

Why it matters

WebMCP lets QA treat in-page agent/tool integrations as testable surfaces; new runner features help reproduce order-dependent flakes and capture deterministic video evidence.

Test infrastructure2/10

Introducing Warm Agents — TeamCity plugin to keep build/test agents pre-started

JetBrains published the Warm Agents TeamCity plugin to maintain a target count of idle, pre-started cloud agents per image, exposing Prometheus metrics and REST API hooks for dynamic control and scheduling.

Why it matters

Reduces queue latency for short PR tests and fast feedback cycles; trades cost for lower test start jitter and improves flakiness triage speed by reducing environment spin-up variance.

Agentic QA / AI-assisted testing2/10

GitHub: Local sandboxing for Copilot generally available

GitHub announced general availability of local sandboxing for Copilot (CLI, app, VS Code Agent Host), enabling running generated code and subagents in local, isolated sandboxes rather than remote execution environments.

Why it matters

Safer local execution makes using Copilot-generated test code and test-driving agents feasible in private environments and improves reproducible, auditable test runs.

GitHub: Purpose-built model for leaked secret detection in the platform

GitHub released a purpose-built model for detecting leaked secrets, integrated into secret-protection tooling to reduce false positives and improve context-aware detection across repos and agent-generated code.

Why it matters

Improves automated pre-merge checks and scan accuracy in CI/test gates, lowering noise for security-related tests and reducing missed secrets in generated test fixtures or agent output.

Test infrastructure / Performance testing3/10

Kubernetes guidance: shift to cgroup v2 and test infrastructure impact

Kubernetes published guidance on shifting to cgroup v2 (Kubernetes v1.31+), describing unified hierarchies and changes to resource isolation and accounting that affect container behavior and scheduler interaction.

Why it matters

cgroup v2 changes can alter CPU/memory throttling and resource isolation for test runners, affecting performance tests, flaky resource-sensitive tests, and CI worker sizing strategies.
